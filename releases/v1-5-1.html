PROJECTENGINE RELEASE · v1.5.1

More Reliable Excel Scheduling, Critical Path and Project Reporting

Fixes stale schedule calculations, multiple dependency analysis, Dashboard warnings, S-Curve fractional progress, Gantt recovery and project migration integrity.

Official GitHub releaseDownload latest ProjectEngine

ProjectEngine v1.5.1 is a reliability-focused update to its Excel-native scheduling and project controls engine. It fixes cases where planning, reporting or migrations could appear successful despite stale, incomplete or misleading results.

More accurate scheduling and critical-path analysis

Task type changes, deleted activities and WBS edits now invalidate affected incremental calculations more reliably. Multiple FS, SS and FF links between the same tasks are retained for path and float analysis, with results no longer dependent on link entry order. Relevant calendar calculations use applicable working days; invalid or duplicate task IDs are caught before corrupting the schedule. Parent dates are recalculated after deletions.

Dashboard indicators you can trust

The Dashboard no longer incorrectly reports no significant schedule drift when substantial delays are present. A summary can now reflect a planned-to-start child task that is still at 0% progress. Completion criteria are applied consistently, unknown or unavailable analytics are distinguished from valid results, and failed snapshot operations do not claim a successful save.

Gantt dependency graphics that recover

Dependency caches and rendered routes are checked against expected links, not merely against the existence of a graphical layer. Missing or damaged links can be rebuilt during normal refresh. If SVG rendering is unavailable, the existing dependency-line fallback can be used, with a return to SVG when it works again. SUMMARY view continues to hide dependency graphics.

Exact fractional S-Curve progress

Short activities no longer lose fractional-day progress during time-phased distribution. Daily actual and remaining contributions conserve the weighted WBS total, so partial progress is represented rather than truncated.

Safer project import and migration

User-authored formulas retain their original expressions even when references may need manual review, with explicit warnings when formula dependencies cannot be guaranteed. Invalid identifiers and incompatible imports are rejected; unsupported historical data is reported instead of silently omitted. Supported input formatting and workbook presentation are preserved.

Fewer false success messages

Write failures and partially completed operations are propagated instead of being reported as successful. Safeguards cover Gantt drag rollback, bulk event-history and acknowledgement updates, scenario creation, and preservation of existing Excel settings.

More reliable localization and tutorial behavior

Failed language changes restore previous settings and visible headers, including diagnostics if recovery itself fails. Temporary tutorial highlighting no longer leaves a successfully saved workbook marked as modified. Event-history input protection and date/message formatting were also refined.

Efficient storage for sparse task IDs

The calculation table now scales with the number of actual tasks rather than the largest task ID. In one measured two-task case using IDs 1 and 10000, synchronization dropped from 10,000 rows and 3.19 s to 2 rows and 0.15 s. This is a specific sparse-ID benchmark, not a universal speed claim; tests on schedules around 1,200 tasks showed broadly comparable performance with operation-dependent variation.

Using this release

Back up your existing project and download the prepared .xlsm workbook from GitHub. Import supported data into the new workbook, review any formula or migration warnings, and run the relevant updates. For the full scope and limitations, consult the official release notes.
